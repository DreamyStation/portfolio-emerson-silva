Publicar.

Um site só existe para o mundo quando está num servidor que fica ligado o tempo todo. Aqui você guarda o histórico do projeto com o Git, envia ao GitHub e vê o site ganhar um endereço público com HTTPS, sem pagar hospedagem.

1 · Quatro ideias

Do seu computador para o link.

Publicar é copiar a pasta do seu projeto para um servidor e dar a ele um nome.

GitO caderno de versões

Guarda o histórico de cada mudança. Cada commit é uma foto do projeto, com uma mensagem que explica o que mudou.

GitHubO armário na nuvem

Um servidor que guarda projetos Git. Com o GitHub Pages, ele também publica a pasta como um site gratuito.

Hospedagem e DNSA casa e o endereço

A hospedagem é o servidor que serve o site. O DNS traduz o nome (voce.github.io, ou um domínio próprio) para esse servidor.

HTTPSO cadeado

Criptografa a conversa entre o visitante e o site. Hoje é obrigatório: os navegadores avisam quando falta.

2 · Cola de publicação

Os comandos do dia da publicação.

  • git inittransforma a pasta em um repositório Git
  • git add .prepara todos os arquivos para o próximo commit
  • git commit -m "mensagem"salva uma versão no histórico
  • git remote add origin URLliga a pasta ao repositório do GitHub
  • git push -u origin mainenvia o histórico para o GitHub
  • curl -I URLconfere se o site responde e com qual código
  • nslookup dominio.com.brmostra para onde o DNS aponta um domínio
  • echo 'dominio' > CNAMEdiz ao GitHub Pages qual domínio próprio usar
