Backend e API.

Até aqui tudo rodava no navegador. Mas um pedido precisa ser guardado, um preço precisa ser consultado, e isso exige um servidor com banco de dados: o backend. A conversa entre o site e o backend acontece por uma API. Aqui você conversa com um servidor de mentira e faz o site usar os dados dele.

1 · Quatro ideias

Como o site conversa com o servidor.

Pense no restaurante da aula 1: o backend é a cozinha, e a API é o cardápio de pedidos que a cozinha aceita.

BackendA cozinha

Programa no servidor que guarda dados (o banco de dados) e aplica as regras: validar um pedido, calcular um total.

APIO cardápio de pedidos

Lista do que o servidor aceita fazer: listar itens, criar pedido. Cada pedido tem um endereço, chamado endpoint, como /api/itens.

JSONO formato dos dados

Texto organizado que tanto o servidor quanto o JavaScript entendem: {"item": "Pão", "qtd": 2}.

Códigos HTTPComo foi o pedido

200 deu certo, 201 criado, 404 não existe, 422 dados inválidos. O código vem sempre junto da resposta.

2 · Cola de HTTP

Verbos e códigos.

  • GET /api/itenspede dados sem alterar nada
  • POST /api/pedidosenvia dados para o servidor criar algo
  • PUT e DELETEatualizam e apagam (não usados neste treino)
  • curl /api/itensfaz um GET pelo terminal e mostra a resposta
  • curl -X POST /api/pedidos -d '{...}'faz um POST com um corpo em JSON
  • fetch("/api/itens")faz o GET de dentro do JavaScript da página
  • 200 · 201sucesso · criado
  • 404 · 422não existe · dados inválidos
